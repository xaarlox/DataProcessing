# Оптимізація обробки великих наборів даних на Python

## 1. Огляд завдання

Метою цього завдання є демонстрація різних підходів до обробки великих масивів даних (100 мільйонів елементів) та
порівняння їхньої продуктивності. Ми оцінюємо три методи:

Простий підхід: Стандартні цикли for.

Паралельні обчислення: Розподілені обчислення за допомогою модуля multiprocessing.

Оптимізований підхід: Векторизовані операції з використанням бібліотеки NumPy.

## 2. Результати тестування

Тестування проводилося на згенерованому наборі з 10,000,000 елементів 10 разів, щоб вирахувати середні значення для
кожного способу. Отримані результати:

| Метод                         | Час виконання (сек) | Ефективність        |
|-------------------------------|---------------------|---------------------|
| Простий (for-loop)            | ~1.24               | Повільно            |
| Паралельний (Multiprocessing) | ~0.81               | Покращено           |
| Оптимізований (NumPy)         | ~0.04               | Найкращий результат |

## 3. Аналіз методів та "вузьких місць"

### Простий підхід (Standard Python)

Звичайний цикл for у Python є найповільнішим для математичних задач через:

- Інтерпретованість: Python — динамічна мова. Кожна ітерація циклу супроводжується перевіркою типів об'єктів та іншими
  системними витратами.

- Overhead об'єктів: Кожне число в списку Python — це повноцінний об'єкт, який займає багато пам'яті та сповільнює
  доступ
  до даних.

### Паралельний підхід (Multiprocessing)

Цей метод виявився майже вдвічі швидшим за звичайний цикл, але все одно не є ідеальним для цієї конкретної задачі.

Чому це швидше: Кожен робочий процес (worker) отримує власну копію інтерпретатора Python, саме це дозволяє обходити
Global Interpreter Lock (GIL), створюючи окремі процеси ОС. Це дозволяє використовувати всі
доступні ядра процесора одночасно.

Чому це не оптимально:

Низька обчислювальна складність при великому обсязі даних. Операція x^2
виконується процесором за наносекунди. Час, який витрачає Python на те, щоб розбити масив, упакувати його в байтові
потоки (Pickling), передати іншому процесу, а потім розпакувати назад, перевищує час самих обчислень.

У результаті ми отримуємо ситуацію, де процесор більше "спілкується", ніж "працює". Це називається високими накладними
витратами на комунікацію (High Communication Overhead).

Цей метод стає максимально ефективним у задачах, які називаються Compute-Intensive (важкі обчислення). Це випадки, де
даних відносно небагато, але алгоритм їх обробки складний і довгий.

Приклади: Обробка відео (застосування складних фільтрів до кожного кадру), Криптографія (перебір паролів, шифрування
великих блоків), Складне моделювання (математичні симуляції фізичних процесів, де кожна ітерація потребує тисяч
підрахунків).

### Оптимізований підхід (NumPy)

NumPy є беззаперечним лідером, оскільки він докорінно змінює принцип роботи з даними:

- Безперервна пам'ять: NumPy використовує масиви в стилі мови C, де дані зберігаються одним суцільним блоком.

- Векторизація: Замість обробки кожного числа окремо, NumPy використовує інструкції Single Instruction, Multiple
  Data. Це дозволяє процесору виконати одну операцію над цілим блоком чисел за один такт.

- Виконання на рівні C: Основні обчислення відбуваються у скомпільованому коді C, повністю ігноруючи повільний
  інтерпретатор Python.

Важливе зауваження щодо типів даних при роботі з Numpy:

Під час роботи з масивами понад 10 млн елементів виникає проблема Integer Overflow (переповнення цілого числа). Оскільки
сума квадратів таких чисел перевищує ліміт стандартного 64-бітного цілого числа (int64), NumPy може видавати
некоректні результати.

Для вирішення цієї проблеми в оптимізованому методі було використано тип даних float64. Це дозволило:

- Уникнути переповнення: Тип float64 має значно ширший діапазон значень порівняно з int64.

- Зберегти швидкість: NumPy продовжує використовувати векторні інструкції процесора (SIMD) для чисел із рухомою комою,
  що забезпечує колосальну перевагу над звичайними циклами.

Валідація результатів між методами проводилася за допомогою функції np.isclose, оскільки при роботі з великими числами
типу float можливі невеликі розбіжності в останніх знаках після коми через особливості арифметики з рухомою комою.

### 4. Висновки

Для обробки числових даних у Python `векторизація (NumPy)` завжди повинна бути пріоритетом. `Multiprocessing` варто
використовувати для "важких" завдань, які неможливо векторизувати, де приріст швидкості від паралельності перевищує
витрати на створення процесів.
